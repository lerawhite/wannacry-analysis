The `p__argc` variable is used to determine the number of command-line arguments supplied to the sample. The resulting value determines which execution path is *selected*.

If fewer than two arguments are present, execution proceeds to the initial execution path at [0x00407F20](0x00407F20.md), which performs **persistence-related operations and deployment of the ransomware core**.

If two or more arguments are present, execution proceeds through the **service-oriented path**. This path prepares the `mssecsvc2.0` service for execution at [0x00407FA0](0x00407FA0.md) and subsequently enters the *Windows Service Control Manager* through `StartServiceCtrlDispatcherA` at [0x00408000](0x00408000.md) .

          │                 │
       < 2 args          >= 2 args
          │                 │

          │                 │
 Persistence +         Service preparation
 ransomware core            │

### `p__argc < 2`


```text
Call 0x00407F20
    ├── Persistence-related operations
    └── Ransomware core deployment
```

See [0x00407F20](0x00407F20.md).

### `OpenSCManagerA`

`OpenSCManagerA` is called to obtain a handle to the local Service Control Manager (SCM).

```c
SC_HANDLE OpenSCManagerA(
    LPCSTR lpMachineName,
    LPCSTR lpDatabaseName,
    DWORD  dwDesiredAccess
);
```

Observed arguments:

```text
lpMachineName  = NULL          // local computer
lpDatabaseName = NULL          // SERVICES_ACTIVE_DATABASE
dwDesiredAccess = SC_MANAGER_CONNECT (value == F003F)
```

The returned handle is subsequently used to access the `mssecsvc2.0` service.

---
### `OpenServiceA`

`OpenServiceA` uses the SCM handle to obtain a handle to the `mssecsvc2.0` service.

```c
SC_HANDLE OpenServiceA(
    SC_HANDLE hSCManager,
    LPCSTR    lpServiceName,
    DWORD     dwDesiredAccess 
);
```

Observed arguments:

```text
hSCManager     = handle returned by OpenSCManagerA
lpServiceName  = "mssecsvc2.0"
dwDesiredAccess = SERVICE_QUERY_CONFIG | SERVICE_CHANGE_CONFIG (value == F01FF)
```

The returned service handle is then used by the subsequent service-management logic at  [0x00407FA0](0x00407FA0.md).

The argument-bearing path proceeds with the service-oriented execution flow:

```text
0x00407FA0
    ↓
Service preparation
    ↓
StartServiceCtrlDispatcherA
    ↓
0x00408000 (ServiceMain)
```

See [0x00407FA0](0x00407FA0.md) and [0x00408000](0x00408000.md) .

### `StartServiceCtrlDispatcherA`

The function receives a pointer to an array of `SERVICE_TABLE_ENTRYA` structures:

```c
BOOL StartServiceCtrlDispatcherA(
    const SERVICE_TABLE_ENTRYA *lpServiceTable
);
```

Each entry associates a service name with its corresponding `ServiceMain` function. The array is terminated by an empty structure.

```c
typedef struct _SERVICE_TABLE_ENTRYA {
    LPSTR                    lpServiceName; // Name of service
    LPSERVICE_MAIN_FUNCTIONA lpServiceProc; // Pointer to ServiceMain
} SERVICE_TABLE_ENTRYA, *LPSERVICE_TABLE_ENTRYA;
```

Here is what the stack looks like before the call `StartServiceCtrlDispatcherA`:
![](../Screens/0x00408090%20Stack%20before%20StartServiceCtrlDispatcherA.png)

The stack state immediately before the call shows:

```text
0x0019FE6C → lpServiceTable
```

The referenced service table contains:

```text
lpServiceName = "mssecsvc2.0"
lpServiceProc = 0x00408000
```

`IOC` - `lpServiceName = "mssecsvc2.0"`.

Therefore, when the Service Control Manager dispatches this service, execution is transferred to [0x00408000](0x00408000.md).
