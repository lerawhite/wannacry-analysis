### 0x00401370  Table-Driven Network Processing Routine

`0x00401370` is a large table-driven network processing routine responsible for executing protocol operations described by entries in a global descriptor table.

The function allocates a large local stack frame and iterates over a table located at `0x00431480`. Each entry has a fixed stride of `0x2728` bytes, with the first field at `[ESI]` determining the operation type.

The observed operation types include:

- **Type 2** — creates a TCP socket, builds a `sockaddr_in` structure using `inet_addr()` and `htons()`, and establishes a connection with `connect()`. The resulting socket is stored in a network context created by `0x00408390`.
    
- **Type 3** — retrieves the corresponding network context and closes its socket with `closesocket()`.
    
- **Type 0** — prepares a data buffer through `0x00401190` and transmits the resulting data through `send()`.
    
- **Type 1** — receives data with `recv()` and, depending on the descriptor contents, extracts fields associated with `treeid` and `userid` from the received buffer.
    

The routine therefore implements a state-driven network/protocol engine rather than a single isolated network operation. Its structure provides explicit support for connection establishment, transmission, reception, and extraction of SMB-related session state.

Of particular interest are the string comparisons against:

```text
"treeid"
"userid"
```

These fields are consistent with SMB session/tree state used by the subsequent protocol processing.

### DOUBLEPULSAR Relationship

The complete protocol implementation behind `0x00401370` was not reverse engineered further. The routine contains a substantial amount of auxiliary network logic and would require significant additional analysis of its descriptor table and helper functions to reconstruct the exact protocol sequence.

For this project, that level of analysis is unnecessary. The surrounding code already provides sufficient evidence to identify the network stage as **DOUBLEPULSAR-related**.

The main evidence is:

1. `0x00401370` performs structured SMB/network communication and maintains `treeid`/`userid` state.
    
2. The surrounding execution path performs additional SMB transaction-based communication.
    
3. The same network component contains `0x00406ED0`, which implements the known DOUBLEPULSAR XOR-key derivation algorithm.
    
4. The following `0x004072A0` path uses the derived value in the subsequent payload-transfer logic.
    
5. The overall execution chain connects SMB communication with the previously constructed in-memory payload buffers.
    

Therefore, the `0x00401370` stage is treated in this analysis as part of the **DOUBLEPULSAR-related network path**.

A complete reconstruction of the DOUBLEPULSAR protocol and its remote-side implementation is outside the scope of this project. The analysis instead stops at the point where the available static evidence is sufficient to establish the relationship and proceeds to the payload-transfer stage.
