# Network Subsystem Initialization Gate - `0x00407B90`

## 1. Overview

Function `0x00407B90` is the **initialization gate for the subsequent network subsystem**.

Its first operation is `WSAStartup`. The return value of this call determines whether the remaining network initialization is executed:

```text
WSAStartup
   │
   ├── failure → return 0
   │
   └── success
         │
         ├── 0x00407620
         └── 0x00407A20
```

This makes `0x00407B90` an **excluding / gating function**: failure at this stage prevents the execution path in `0x00407BD0` from creating the subsequent network workers.

---

## 2. Winsock Initialization

The function allocates `0x190` bytes of stack space:

```asm
00407B90 | 81EC 90010000 | sub esp,190
```

It then prepares a buffer for `WSAStartup`:

```asm
00407B96 | 8D4424 00 | lea eax,[esp]
00407B9A | 50        | push eax
00407B9B | 68 02020000 | push 202
00407BA0 | E8 471C0000 | call <JMP.&WSAStartup>
```

The two arguments correspond to the standard Winsock initialization interface:

```c
WSADATA wsaData;

WSAStartup(
    MAKEWORD(2, 2),
    &wsaData
);
```

Specifically:

```text
0x0202
    │
    └── requested Winsock version 2.2

[ESP]
    │
    └── pointer to WSADATA structure receiving
        information about the initialized Winsock environment
```

Thus, the sample explicitly requests **Winsock 2.2** before entering its network-specific initialization routines.

---

## 3. Exclusive Failure Path

The return value of `WSAStartup` is immediately checked:

```asm
00407BA5 | 85C0 | test eax,eax
00407BA7 | 74 09 | je 407BB2
00407BA9 | 33C0 | xor eax,eax
00407BAB | 81C4 90010000 | add esp,190
00407BB1 | C3 | ret
```

The logic is:

```c
if (WSAStartup(MAKEWORD(2, 2), &wsaData) != 0)
    return 0;
```

Unlike many initialization routines where failure may be logged or partially tolerated, this function has a clear binary outcome:

```text
WSAStartup == failure
        │
        ▼
      EAX = 0
        │
        ▼
   0x00407B90 returns
        │
        ▼
   0x00407BD0 terminates
```

Therefore, a failed Winsock initialization **excludes the entire subsequent worker initialization path**.

This is the critical architectural role of `0x00407B90`.

---

## 4. Successful Initialization Path

When `WSAStartup` succeeds, execution continues with:

```asm
00407BB2 | E8 69FAFFFF | call wannacry.407620
00407BB7 | E8 64FEFFFF | call wannacry.407A20
00407BBC | 81C4 90010000 | add esp,190
00407BC2 | C3 | ret
```

The function therefore performs two additional initialization stages:

```text
WSAStartup
    │
    ▼
0x00407620
    │
    ▼
0x00407A20
    │
    ▼
return
```

The exact responsibilities of [0x00407620](0x00407620.md) and [0x00407A20](0x00407A20.md) are established by their individual analyses. Within `0x00407B90`, their significance is that **both are reachable only after successful Winsock initialization**.

The successful path returns without explicitly modifying `EAX` after these calls, so the return value observed by the caller is determined by the final called function's return value.

---

## 5. Relationship With `0x00407BD0`

The importance of this function becomes clear when correlated with its caller:

```asm
00407BD0 | call 0x00407B90
00407BD5 | test eax,eax
00407BD7 | jne 0x00407BDA
00407BD9 | ret
```

The resulting dependency is:

```text
                  0x00407BD0
                       │
                       ▼
                  0x00407B90
                       │
              ┌────────┴────────┐
              │                 │
          EAX == 0          EAX != 0
              │                 │
              ▼                 ▼
           return       worker initialization
                              │
                       ┌──────┴──────┐
                       ▼             ▼
                  0x00407720    0x00407840
```

Consequently, `0x00407B90` isnt merely a helper responsible for calling `WSAStartup`. It defines whether the subsequent network-worker execution path is entered at all.

---

## 6. Research Report

Function `0x00407B90` serves as the **Winsock and network-subsystem initialization gate** for the service execution path.

Its behavior can be summarized as:

```c
int NetworkInitializationGate(void)
{
    WSADATA wsaData;

    if (WSAStartup(MAKEWORD(2, 2), &wsaData) != 0)
        return 0;

    0x00407620();
    0x00407A20();

    return /* result of final initialization stage */;
}
```

The key finding is the **exclusive dependency on successful Winsock initialization**. A `WSAStartup` failure causes `0x00407B90` to return zero, which in turn causes `0x00407BD0` to terminate before creating its worker threads.

Thus:
**`0x00407B90` forms the initialization gate between the Windows service execution path and the subsequent network-worker subsystem.**
