`*Purpose - Establish persistence through a Windows service.*`

---

**Figure 1. `0x00407C40` View in x64dbg**
![](0x00407C40%20View%20in%20x64dbg.png)

The persistence routine constructs the service binary path and uses it to create an automatic Windows service.

---
### Command-line construction

The routine first calls `sprintf` to construct a **command line** in a stack buffer. The resulting string combines the executable path stored at `0x0070F760` with the argument:

```text
-m security
```

The resulting command line is subsequently passed as the `lpBinaryPathName` argument of `CreateServiceA`.

### Service Manager access

The routine then calls `OpenSCManagerA` to obtain a handle to the local Service Control Manager.

**Figure 3. `0x00407C40` `OpenSCManagerA`**
![](0x00407C40%20View%20argc%20OpenSCManagerA.png)


If `OpenSCManagerA` fails, execution follows the failure path and the persistence routine terminates.

If a valid SCM handle is obtained, the sample calls `CreateServiceA` with the following observed parameters:

|Parameter|Observed value|
|---|---|
|`hSCManager`|SCM handle|
|`lpServiceName`|`mssecsvc2.0`|
|`lpDisplayName`|`Microsoft Security Center (2.0)`|
|`dwDesiredAccess`|`0xF01FF` (`SERVICE_ALL_ACCESS`)|
|`dwServiceType`|`0x10` (`SERVICE_WIN32_OWN_PROCESS`)|
|`dwStartType`|`2` (`SERVICE_AUTO_START`)|
|`dwErrorControl`|`1`|
|`lpBinaryPathName`|`<executable path> -m security`|
|`lpLoadOrderGroup`|`NULL`|
|`lpdwTagId`|`NULL`|
|`lpDependencies`|`NULL`|
|`lpServiceStartName`|`NULL`|
|`lpPassword`|`NULL`|

The service is configured with `SERVICE_AUTO_START`, causing Windows to start it **automatically during system startup.

The service name is `mssecsvc2.0`, while the display name is `Microsoft Security Center (2.0)`. The `-m security` argument causes the executable to enter the argument-bearing execution path discussed in 0x00408090.


`IOC: -m security, mssecsvc2.0 , Microsoft Security Center (2.0)`. 

**Why important:** Service name created by the sample; useful for host-based detection and correlating persistence artifacts.

---
### Service start

After creating the service, the routine calls `StartServiceA`, initiating the newly created service immediately rather than waiting for the next system startup.
