### 0x00408E50 - IPv4 Host Address Enumeration

`0x00408E50` is responsible for enumerating IPv4 addresses within a network range and storing the resulting addresses in a dynamically allocated array.

The function receives three parameters:

![](../Screens/0x00408E50%20Stack%20before%20calling.png)

```text
param_1 → destination address-array structure
param_2 → lower IPv4 boundary
param_3 → upper IPv4 boundary
```

The destination structure can be reconstructed as:

```c
struct AddressArray {
    uint32_t *begin;       // +0x04
    uint32_t *end;         // +0x08
    uint32_t *capacity;    // +0x0C
};
```

The number of stored elements is calculated from:

```c
(end - begin) / sizeof(uint32_t)
```

while available capacity is determined from:

```c
(capacity - end) / sizeof(uint32_t)
```

### IPv4 Range Enumeration

The function first converts both boundaries with `htonl()` and then iterates through the complete range:

```c
for (; lower <= upper; lower++) {
    ...
}
```

Before an address is inserted into the destination array, the function checks its lowest byte:

```c
if ((address & 0xFF) != 0 &&
    (address & 0xFF) != 0xFF)
```

This excludes addresses ending in `.0` and `.255`.

Therefore, when the function receives a `/24` range such as:

```text
Network address   : 192.168.124.0
Broadcast address : 192.168.124.255
```

the resulting host-address range is:

```text
192.168.124.1
192.168.124.2
...
192.168.124.253
192.168.124.254
```

The selected IPv4 value is converted with `ntohl()` before being stored in the destination array.

### Dynamic Array Management

The function implements dynamic growth of the destination array.

When the current `end` pointer reaches the allocated capacity, a larger buffer is allocated. Existing elements are copied into the new buffer, the current IPv4 address is appended, the previous buffer is released with `free()`, and the `begin`, `end`, and `capacity` pointers are updated.

For an already populated array containing at least two elements, the allocation logic approximately doubles its capacity:

```text
new capacity ≈ current element count × 2
```

When sufficient capacity is available, the new address is written directly at the current `end` position and the `end` pointer is advanced by one `DWORD`.

The helper functions used during this process ([0x00409050](0x00409050.md), [0x00409080](0x00409080.md), [0x004090B0](0x004090B0.md), and [0x004097FE](0x004097FE.md)) implement array copying, single-element copying, and memory release. 

### Relationship with 0x00409160

The caller `0x00409160` calculates the boundaries passed to this function from the local IPv4 address and subnet mask:

```c
network   = ip & subnet_mask;
broadcast = ip | ~subnet_mask;
```

The resulting values are passed to `0x00408E50` as:

```text
param_2 = network address
param_3 = broadcast address
```

For the network observed during dynamic analysis:

```text
Local IP         : 192.168.124.128
Subnet mask      : 255.255.255.0

Network address  : 192.168.124.0
Broadcast        : 192.168.124.255
```

`0x00408E50` therefore converts this network configuration into a list of candidate host addresses.

### Behavioral Conclusion

The confirmed behavior of `0x00408E50` is:

```text
Local IPv4 network range
        ↓
Network / broadcast boundaries
        ↓
Enumerate every address
        ↓
Exclude .0 and .255
        ↓
Convert address representation
        ↓
Append IPv4 address to dynamic array
```

The function itself doesnt perform network communication or scanning. It only constructs the collection of candidate IPv4 addresses. The subsequent use of these addresses must therefore be established by analyzing the worker routine that consumes the generated array.
