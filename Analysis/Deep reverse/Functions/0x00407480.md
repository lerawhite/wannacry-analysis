# Function `0x00407480` - Non-Blocking TCP/445 Target Reachability Check

## Overview

`0x00407480` performs a preliminary network reachability check for an IPv4 address supplied by its caller.

The function creates an IPv4 TCP socket, switches the socket to non-blocking mode, attempts to connect to the supplied address on TCP port `445`, monitors the resulting socket state using `select()`, closes the socket, and returns the result of `select()` to the caller.

This function represents an important filtering stage in WannaCry's network-target processing architecture. Its result determines whether the target proceeds to the next stage of processing in `0x004076B0`.

The overall architecture reconstructed during the analysis is:

```text
00409160
    │
    │ Generate candidate IPv4 addresses
    ▼
00407720
    │
    │ Distribute targets
    ▼
004076B0
    │
    │ target IP
    ▼
00407480
    │
    │ TCP/445 reachability check
    ├───────────────┐
    │               │
  fail            pass
    │               │
    ▼               ▼
 discard          00407540
 target             │
                    ▼
             further processing
```

# 1. Target Address and Socket Parameters

The function receives the target IPv4 address as its first argument:

```asm
00407486 | mov ecx,dword ptr ss:[esp+124]
```

The value is subsequently stored into the local network address structure:

```asm
004074B0 | mov dword ptr ss:[esp+10],ecx
```

The function initializes the destination port:

```asm
004074A2 | push 1BD
004074BB | call htons
```

`0x1BD` corresponds to decimal port `445`.

The result of `htons()` is stored into the local address structure:

```asm
004074C5 | mov word ptr ss:[esp+16],ax
```

The address family is initialized as:

```asm
004074B4 | mov word ptr ss:[esp+C],2
```

where:

```text
AF_INET = 2
```

Therefore, the destination address is conceptually:

```c
struct sockaddr_in target;

target.sin_family = AF_INET;
target.sin_port   = htons(445);
target.sin_addr   = target_ip;
```

For the analyzed runtime execution, the target that passed this stage was:

```text
192.168.124.128
```

---

# 2. TCP Socket Creation

The function creates the socket using:

```asm
004074C0 | push 6
004074C2 | push 1
004074C3 | push 2
004074CA | call socket
```

The arguments correspond to:

```c
socket(
    AF_INET,
    SOCK_STREAM,
    IPPROTO_TCP
);
```

Therefore, the function creates an IPv4 TCP socket.

The returned socket handle is stored in `ESI`:

```asm
004074CF | mov esi,eax
```

The function checks for `INVALID_SOCKET`:

```asm
004074D1 | cmp esi,FFFFFFFF
004074D4 | jne 004074E1
```

If socket creation fails, the function immediately returns zero.

---

# 3. Non-Blocking Socket Configuration

After successfully creating the socket, the function enables non-blocking mode:

```asm
004074E1 | lea edx,dword ptr ss:[esp+18]
004074E5 | push edx
004074E6 | push 8004667E
004074EB | push esi
004074EC | call ioctlsocket
```

The control code `0x8004667E` corresponds to `FIONBIO`.

The associated mode value is `1`, enabling non-blocking operation.

Conceptually:

```c
u_long mode = 1;

ioctlsocket(
    socket,
    FIONBIO,
    &mode
);
```

This is significant because the subsequent `connect()` operation is performed using a non-blocking socket. The worker therefore does not need to remain synchronously blocked while waiting for the connection attempt to complete.

**Figure 2. `0x00407480` ioctlsocket args**
![](../Screens/0x00407480%20Ioctlsocket%20()%20args.png)

Return value == `0x00000000`, means success.

0040750D | call connect

Therefore, the values are:

```asm
arg1 = 0x000004C0
arg2 = 0x03E7FE08
arg3 = 0x00000010
```

Which corresponds to:

```C
connect(
    0x000004C0,

```

The value `0x10` equals **16 bytes**, which is the standard size of `sockaddr_in`.


**Structure sockaddr_in:**
```C
struct sockaddr_in {
    short          sin_family;   // 2 bytes
    unsigned short sin_port;     // 2 bytes
    struct in_addr sin_addr;     // 4 bytes
    char           sin_zero[8];  // 8 bytes
};
```

## Examining the memory at `0x03E7FE08`

The memory contains:

```
03E7FE08  BD010002
03E7FE0C  807CA8C0
03E7FE10  00000000
03E7FE14  00000000
```

These are 16 bytes:

```
BD 01 00 02
80 7C A8 C0
00 00 00 00
00 00 00 00
```


Now we can interpret them according to `sockaddr_in`.

```
+0x00  sin_family
+0x02  sin_port
+0x04  sin_addr
+0x08  sin_zero[8]
```

This matches perfectly.

The value:

```
03E7FE08  BD010002
```

should be split into two WORDs:

```
offset +0x00:
02 00

offset +0x02:
BD 01
```

Therefore:

```
sin_family = 0x0002
sin_port   = 0x01BD
```

---
### Offset + 0x00 - `sin_family`

The bytes:

```
02 00
```

represent:

```
0x0002
```

which is:

```
AF_INET
```

Therefore, the destination uses IPv4.

---
### Offset + 0x02 - `sin_port`

The bytes in memory are:

```
BD 01
```

Since the port is stored in **network byte order**, it should be interpreted as:

```
0xBD01
```

and converted from network byte order:

```
0x01BD
```

which is:

```
445/TCP
```

And then:

This provides direct runtime evidence that the function prepares a TCP connection to:

```

```

# 5. Monitoring the Non-Blocking Connection

After initiating the connection, the function invokes `select()`:

```asm
00407512 | lea ecx,dword ptr ss:[esp+1C]
00407516 | lea edx,dword ptr ss:[esp+24]
0040751A | push ecx
0040751B | push 0
0040751D | push edx
0040751E | push 0
00407520 | push 0
00407522 | call select
```

**Figure 5. `0x00407480` stack before Select ()**
![](../Screens/0x00407480%20Stack%20before%20call%20Select%20().png)

---


The local structures initialized by the function are passed to `select()` to monitor the state of the non-blocking connection attempt.

Conceptually:

```text
non-blocking connect()
        │
        ▼
     select()
        │
        ├── target not reachable
        │
        └── socket becomes ready
```

The exact internal organization of the local `fd_set` structures isnt necessary to establish the primary role of the function.

The important API sequence is:

```text
socket()
   ↓
ioctlsocket(FIONBIO)
   ↓
connect()
   ↓
select()
```

This sequence demonstrates that `0x00407480` implements a non-blocking TCP connectivity check rather than directly performing an SMB request.

# 6. Socket Cleanup and Return Value

Immediately after `select()`:

```asm
00407527 | push esi
00407528 | mov edi,eax
0040752A | call closesocket
```

The return value of `select()` is preserved in `EDI`, while the socket is closed.

The saved value is then returned:

```asm
0040752F | mov eax,edi
```

Conceptually:

```c
int result = select(...);

closesocket(socket);

return result;
```

The function therefore doesnt maintain the TCP connection after this preliminary check.

Its purpose is to determine whether the target should proceed to the next processing stage.

And in our example it returns  **1**, means **success**.

# 7. Relationship With the Target-Generation Architecture

`0x00407480` shouldnt be considered an isolated socket routine. Its importance becomes clear when it is viewed together with the previously analyzed functions.

`0x00409160` performs local network-interface enumeration and constructs candidate IPv4 addresses.

These targets are subsequently distributed by the worker infrastructure, with the target address being passed individually into the per-target processing path.

The relevant execution flow is:

```text
Local network configuration
          │
          ▼
     00409160
          │
          │ candidate IPv4 addresses
          ▼
     00407720
          │
          │ target distribution
          ▼
    004076B0(IP)
          │
          ▼
     00407480(IP)
          │
          │ TCP/445 reachability test
          ▼
       Result
       /    \
    fail    pass
     │        │
     ▼        ▼
  discard   00407540
               │
               ▼
       further target processing
```

This establishes a two-stage target-processing architecture:

```text
Target enumeration
       │
       ▼
TCP/445 filtering
       │
       ▼
SMB / propagation processing
```

The individual target addresses are therefore not immediately subjected to the more expensive SMB-related logic. They first pass through the TCP/445 reachability stage.

# 10. Why This Preliminary Check Is Used

The function provides a relatively inexpensive filtering stage before more substantial network processing is performed.

Conceptually:

```text
Candidate target
       │
       ▼
TCP/445 check
       │
       ├── unavailable → stop processing
       │
       └── reachable → continue
                         │
                         ▼
                    00407540
                         │
                         ▼
                    00401980
                         │
                         ▼
                     SMB1
```

This is particularly relevant because the preceding network code can generate multiple candidate addresses.

Performing the full SMB-related processing against every candidate would create unnecessary network traffic and consume additional processing resources.

The architecture instead separates:

1. **Candidate generation**
    
2. **Target distribution**
    
3. **TCP/445 filtering**
    
4. **Target-specific processing**
    
5. **SMB protocol interaction**
    

The multithreaded design allows multiple targets to be processed concurrently, while `0x407480` provides an early filtering stage before the deeper protocol logic is executed.

# 11. Relationship With `0x004076B0`

The return value of `0x00407480` directly controls whether the worker continues:

```asm
004076BE | test eax,eax
004076C0 | jle 00407702
```

Conceptually:

```c
if (CheckTCP445(target_ip) <= 0)
    terminate_worker;
```

Only a positive result allows the worker to continue into the subsequent processing path, including the call associated with [0x00407540](0x00407540.md) .

Therefore, `0x00407480` acts as a **gatekeeper between target enumeration and subsequent target-specific processing**.

This relationship is important because it explains why `0x00401980` was reached for `192.168.124.128`: the target first passed the TCP/445 reachability stage.

# 12. Relationship With `0x00401980`

The distinction between the two functions is important.

### `0x00407480`

Performs the transport-level check:

```text
Can TCP/445 be reached?
```

### `0x00401980`

Going to [0x00401980](0x00401980.md) .

Performs the SMB-level qualification:

```text
Does the target respond to the SMB1 protocol exchange
expected by this stage of WannaCry's network logic?
```

The observed architecture is therefore:

```text
             00407480
        TCP/445 reachability
                │
                │ success
                ▼
             00407540
                │
                ▼
             00401980
          SMB1 qualification
                │
                ├── NEGOTIATE
                ├── SESSION_SETUP
                ├── UID extraction
                └── TREE_CONNECT
```

This separation between TCP reachability and application-layer protocol interaction is one of the important architectural findings of the analysis.

# 14. Research Conclusion

Function `0x00407480` represents the TCP-level entry point into WannaCry's SMB target-processing path.

The function:

1. Receives a candidate IPv4 address.
    
2. Creates an IPv4 TCP socket.
    
3. Enables non-blocking operation using `ioctlsocket(FIONBIO)`.
    
4. Attempts to connect to TCP port `445`.
    
5. Uses `select()` to monitor the non-blocking connection.
    
6. Closes the socket.
    
7. Returns the result used by the caller to decide whether the target should continue through the processing pipeline.
    

During the controlled laboratory execution, the Windows 10 VM at:

```text
192.168.124.128:445
```

passed this preliminary reachability stage.

The successful result allowed execution to continue into `0x00407540` and subsequently into the SMB1 qualification routine `0x00401980`, where the actual SMB protocol exchange was reconstructed.

The firewall and SMB configuration performed in the Windows 10 VM were experimental prerequisites that allowed this network path to be observed. They should therefore be considered part of the **analysis environment**, rather than part of WannaCry's own behavior.

The function can consequently be summarized as:

```text
Candidate IPv4 address
        │
        ▼
   00407480
        │
        │ TCP connect :445
        ▼
     select()
        │
        ├── fail → target discarded
        │
        └── pass
             │
             ▼
          00407540
             │
             ▼
          00401980
             │
             ▼
        SMB1 qualification
```
